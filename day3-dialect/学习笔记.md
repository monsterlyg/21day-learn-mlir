# Day 3：Dialect、类型系统与核心方言

## 本日目标

理解 Dialect 如何扩展 MLIR，并掌握读取具体 Operation、类型和属性的基本方法；通过常见核心方言认识 MLIR 的抽象层次。

## 知识点

### 1. Dialect 的职责

Dialect 为相关 Operation、Type、Attribute 和约定提供命名空间与注册入口。方言不是单纯的字符串标签：它承载操作的定义、验证规则、解析/打印和可供 Pass 使用的接口。一个 IR Module 可以混合多个 Dialect。

操作名如 `arith.addf` 中，`arith` 是 Dialect namespace，`addf` 是该方言中的操作名。类型/属性也可能使用方言前缀，例如自定义 `!mydialect.type` 或 `#mydialect.attr`。

### 2. 通用 Operation 与 typed Op

- `Operation*` 是统一底层表示，适合跨 Dialect 的通用工具。
- `arith::AddFOp`、`func::FuncOp` 等 typed wrapper 提供具名 getter/setter 和编译期类型约束。
- `isa<T>` 判断是否属于某个操作类型；`dyn_cast<T>` 尝试转换并可能失败；`cast<T>` 用于已保证类型正确的场景，错误使用会触发断言/未定义的错误路径。
- 对不可信 IR，先 `isa`/`dyn_cast`，不要仅根据字符串强转。

### 3. Type 与 Attribute

- Type 属于 SSA Value 的静态类型，例如整数/浮点、向量、Tensor、MemRef、函数类型、自定义类型。
- Attribute 是不可变的编译期数据，常用于常量值、配置、布局、量化参数等；它不参与运行时 SSA def-use 链。
- 有些操作会把“看似参数”的内容建模为 operand，有些则建模为 attribute，取决于它是否为 SSA 数据流、是否需要运行时变化等语义。
- 类型和属性在 MLIRContext 中通常以 uniqued 不可变对象管理，比较/存储应遵循 MLIR API。

### 4. 常见核心方言地图

- `builtin`：Module、TensorType、函数类型等基础 IR 构件。
- `func`：函数、调用、返回等函数级结构。
- `arith`：整数/浮点算术、比较和常量等标量计算。
- `cf`：显式控制流分支。
- `scf`：结构化控制流，如 if/for/while。
- `tensor`：值语义的多维张量操作。
- `memref`：显式内存引用、内存分配/访问等。
- `linalg`：结构化张量/线性代数计算。
- `affine`：具有仿射索引/循环结构的计算。
- `vector`：向量化计算。
- `llvm`：LLVM IR 语义的低层方言。

以上是地图，不要求一天掌握所有操作。方言的具体可用性取决于 LLVM/MLIR 版本和构建配置。

### 5. 同一计算可处于不同抽象层

高层 Op 可以直接表达 `matmul` 或卷积语义；低层表示可能展开成循环、索引和标量算术。较高层保留更多领域信息，便于做专门优化；lowering 会逐步降低抽象并明确实现细节。学习时要问“该 IR 还保留了什么语义信息”。

### 6. 验证、注册和扩展

方言/操作注册让 parser、verifier 和工具认识相应定义。已注册操作可使用专门解析格式和 verifier；generic form 可用于观察通用 Operation 结构。自定义 Dialect 通常由 ODS/TableGen 辅助生成，后续再系统学习。

## 练习建议

阅读一小段混合 `func`、`arith`、`tensor` 或 `linalg` 的 IR，为每个操作标注所属方言、输入输出类型、抽象层级，以及它保留的语义信息。
