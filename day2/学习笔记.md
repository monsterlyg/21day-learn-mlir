# Day 2：MLIR IR 对象模型与 SSA 数据流

## 本日目标

理解文本 IR 背后的对象关系，特别是 Operation、Value、Block、Region 如何组成 IR，以及 SSA 的定义-使用关系如何表达数据流。

## 知识点

### 1. Operation、Value 与 Type

- **Operation** 表示一次计算、声明、控制流或结构化容器；含 operands、results、attributes、regions 等。
- **Value** 是 SSA 值的通用句柄。它可能是某个 Operation 的 Result，也可能是 Block 的 BlockArgument。
- **Type** 描述 Value 的静态类型，例如 `i32`、`f32`、`tensor<...>`、`memref<...>`、函数类型等。
- 文本里的 `%name` 是打印器分配的名字，程序中应通过 Value 对象引用，不应依赖名字字符串做语义判断。

### 2. SSA 与 Def-Use 链

SSA（Static Single Assignment）要求每个 SSA Value 有一个定义点。Operation 的 Result 是一种定义；BlockArgument 是另一种定义。每个使用点通过 Operand 引用同一个 Value。

```text
%a = arith.constant 2 : i32  ──定义 %a
%b = arith.addi %a, %a : i32 ──两次使用 %a，定义 %b
```

- Def-use：从定义值找到它的所有 uses/users。
- Use-def：从 operand 回到它的定义者。
- 一个值可有零个、一个或多个使用者；不能默认只有一个。
- 定义者查询可能为空，因为 BlockArgument 并非由 Operation 产生。
- SSA 值通常在其定义所在区域的可见性规则内使用；Region 的隔离/捕获规则会影响值能否跨区域引用。

### 3. Block、Region 与 Operation 嵌套

- Region 是一组 Block 的容器，附着在 Operation 上。
- Block 是基本控制流单元，包含有序 Operation 列表和零个或多个 BlockArgument。
- Operation 可以含 Region，因此 IR 是递归嵌套结构，不只是平铺指令列表。
- 函数通常含一个 body Region；入口 Block 的参数对应函数参数。
- 分支目标 Block 的参数常用于传递控制流值；这与 Operation Result 是不同的值来源。
- Module 自身也是 Operation，并在其 Region/Block 中容纳顶层操作。

### 4. 控制流与 Region 语义

MLIR 同时支持显式 CFG（多个 Block、Branch）和结构化控制流方言（例如 `scf.if`、`scf.for`）。控制流操作往往带有 Region；Region 的 terminator（如 `scf.yield`、`func.return`）表达退出或传值方式。Day 2 先认识对象结构，具体控制流语义留到后续专题。

### 5. 遍历与查询方式

- `walk` 可递归遍历嵌套 Operation；遍历顺序/何时可安全修改 IR 需依据所用 API。
- `getOperands()` / `getResults()` 访问 SSA 边；`getUsers()`/use range 访问使用关系。
- `getDefiningOp()` 对 Operation Result 找定义者；对 BlockArgument 返回空。
- `getRegion()`、`getBlocks()`、`getArguments()` 逐层访问嵌套结构。
- 高层 typed API（例如 `func::FuncOp`）能表达特定操作语义；通用 `Operation*` 则适用于通用分析。

### 6. 支配与可见性（概念预告）

CFG 中“定义在使用之前”还不够；定义必须在控制流上支配使用点。MLIR verifier 会依据操作/区域规则检查合法性。复杂控制流的 SSA 正确性需要理解 Dominance；本日建立概念即可，之后再深挖。
