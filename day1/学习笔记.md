# Day 1：MLIR 入门与文本 IR

## 本日目标

建立 MLIR 的整体印象：MLIR 是可扩展的多层级中间表示框架；学习读懂一小段文本 IR，并知道工具、上下文和方言各自负责什么。

## 知识点

### 1. MLIR 在编译器中的位置

MLIR（Multi-Level Intermediate Representation）提供 IR 数据结构、方言扩展机制、解析/打印设施、Pass 基础设施和转换框架。它不是单一固定 IR，也不等同于 LLVM IR。编译器可以在不同抽象层级保留领域语义，再逐步降低到更接近机器的表示。

典型思路：

```text
源程序/模型 → 高层领域 IR → 通用计算 IR → 循环/内存 IR → LLVM IR → 机器码
```

这是一类可能的流水线，不是唯一固定路径；一个项目可定义自己的方言和阶段。

### 2. 方言（Dialect）

Dialect 是一组相关 IR 概念的命名空间和扩展单元，可以定义 Operation、Type、Attribute，以及相关接口和约束。文本形式通常以方言名为前缀，例如 `arith.addf`、`func.func`。Builtin 方言提供 `module`、常用容器等基础结构。

方言承载语义：`arith.addf` 明确表示浮点加法；自定义方言可以表达领域操作。只看操作名不够，还要结合其定义、类型、属性和约束理解语义。

### 3. 文本 IR 的基本读法

```mlir
module {
  func.func @main(%arg0: f32) -> f32 {
    %one = arith.constant 1.0 : f32
    %sum = arith.addf %arg0, %one : f32
    return %sum : f32
  }
}
```

- `module` 是顶层容器；`func.func` 声明函数。
- `@main` 是 Symbol 名称；`%arg0`、`%one`、`%sum` 是 SSA 值名。
- `arith.constant` 和 `arith.addf` 是产生结果的 Operation；`return` 使用 `%sum`。
- `: f32` 表示类型；函数签名也描述参数和返回类型。
- 花括号引入区域内容；缩进只是可读性格式。

### 4. Operation 的组成

Operation 是 MLIR 的核心节点。常见组成包括：操作数（operands）、结果（results）、属性（attributes）、类型、区域（regions）、后继块（successors）和源位置（location）。某个 Operation 不一定包含所有组成部分。Operation 名称通常由 Dialect 和 mnemonic 构成。

区分三个“值”：

- Operand：当前 Operation 消费的 SSA Value。
- Result：当前 Operation 产生的 SSA Value。
- Attribute：附着在 Operation 上的编译期元数据/参数，不是 SSA Value。

### 5. MLIR 工具和程序对象

- `mlir-opt`：解析、验证、运行 Pass pipeline、打印 IR 的通用工具。
- `mlir-translate`：在 MLIR 与其他表示之间转换（具体支持取决于构建）。
- `MLIRContext`：持有方言注册、类型/属性 uniquing 等上下文资源。
- Parser：把文本 IR 变为内存中的 IR 对象；Printer：把 IR 对象序列化为文本。
- Dialect 注册与加载：解析已注册的已知方言通常需要加载/注册相应 Dialect；允许未知操作的 generic 形式是另一种情况。

### 6. 校验与诊断

解析成功表示文本能构造成 IR；Verifier 还会检查操作的结构约束、类型和区域规则。错误诊断中的 Location 用于指向源文件位置。不要把“能解析”误认为“语义正确”。

## 练习建议

用 `mlir-opt` 解析并打印一段含函数、常量、算术操作的 IR；故意改错一个类型，观察 verifier 诊断。然后把 IR 中的 SSA 值、操作、类型、属性和符号分别标出来。
